## 0. 定位判断（先说清楚我的假设）

你说"设计一个农场的场景"，我理解为：**一条完整的农场主题闯关线**（像丛林 / 海岛 / 火山那样的第四个主题），
包含房间图、一套敌人、一个 Boss、主题武器与整活机关。

理由：

1. §1 问题 4 你写的是「闯关模式（暂定丛林、海岛、火山**等**经典场景）」—— 主题列表是开放的，农场可入列；
2. 游戏基调是「轻松欢乐 / Q 版萌系 / 整活向」，农场（会炸的鸡、愤怒的公牛、爆炸南瓜）是**整活素材密度最高**的题材之一；
3. 核心动词是「打 / 射击」，农场作为**战斗关卡**不偏离核心；若做成"种菜经营"则与核心动词冲突，我会反对（见 §11 风险）。

**如果实际想要的是下面两种，说一声我立刻改向**（差异在 §12）：

| 另一种定位 | 差异 |
|---|---|
| **局外基地 / 大厅**（家园，不打怪） | 属元进度系统，会牵动存档结构，需先完成阶段 4；本文 §5-§8 基本作废，只留 §2 视觉 |
| **地牢中的一个特殊房**（农场房） | 成本最小，可立即做；本文压缩为 §4 的单个房间 + 少量机关即可 |

## 1. 农场为什么适合这个游戏

| 维度 | 判断 |
|---|---|
| **整活密度** | ★★★★★ 骑猪撞人、把队友推进干草堆、爆炸南瓜连锁、公牛冲进队友群里 —— 天然喜剧 |
| **萌系造型** | ★★★★★ 圆滚滚的鸡、南瓜、小猪，与 ID-006「怪物造型偏萌诙谐」高度一致 |
| **弹幕可读性** | ★★☆☆☆ **风险项**。户外明亮 + 高作物遮挡，与 §5.1 冲突一直接冲突，需专门适配（见 §9） |
| **房间制兼容** | ★★★☆☆ 开阔户外与「一格一格房间」有张力，用**篱笆田垄切分**解决（见 §3） |
| **内容弹性** | ★★★★☆ 谷仓 / 玉米地 / 鸡舍 / 温室 / 磨坊 / 晒谷场，房间模板可无限扩 |

**一句话定位**：农场是「**明亮的户外弹幕场**」—— 用开阔地形换取更长的弹幕飞行时间（更好读），
同时用篱笆网格把户外切回房间制，是三个主题里**最容易做整活、也最容易在可读性上翻车**的一个。

## 2. 视觉设计

### 2.1 技术规格（沿用 Q1 决策）

- 低多边形模型 + 低分辨率纹理，渲染到低分辨率缓冲再点采样放大
- 推荐 `640×360` 起步（不是 320×180）—— 农场是**明亮场景**，子弹对比度本就吃亏，再降分辨率会不可读
- HUD 保持原生分辨率（`PixelRenderScaler` 已处理分层）

### 2.2 配色板

| 用途 | 色值方向 | 说明 |
|---|---|---|
| 主色调 | 暖黄（麦田 `#E8C06A`）+ 草绿（`#7BA84F`） | 明亮、治愈，与地牢暗色形成主题差异 |
| 辅色 | 谷仓红（`#A8433A`）、原木棕（`#6B4A2F`） | 用于建筑与可交互物，作为视觉锚点 |
| 天空 | 淡蓝偏白（`#BFE0F2`），少量云 | **刻意不做高饱和蓝天** —— 天空是弹幕背景，太抢眼会吃掉子弹 |
| 敌人 | 高饱和低明度（如鸡的橙红 `#E2703A`） | 在暖黄背景上仍能跳出来 |
| 弹幕 | **高饱和冷色 + 深色描边**（青 `#3FD8E0` / 紫 `#B45CE0`） | 冷色在暖色场景里对比最强；描边见 §9.1 |

**关键规则**：场景整体走**低饱和**，把高饱和留给「敌人 + 弹幕 + 可交互物」。
这是所有高可读性游戏的通用做法（背景退后，威胁前进）。

### 2.3 地表与地标

| 元素 | 作用 |
|---|---|
| 篱笆 / 木栅栏 | **房间边界**，兼作视觉分区（见 §3） |
| 红色谷仓 | 大型地标，室内战斗房 |
| 风车 / 磨坊 | 中景地标，叶片是可交互机关 |
| 干草垛 | 掩体 + 整活道具 |
| 水塔 / 筒仓 | 远景剪影，撑起农场天际线 |
| 拖拉机（静态） | 场景叙事 + 掩体 |

### 2.4 光照

- **明亮日光**，Directional Light 主光 + 环境光抬高（ambient 偏暖）
- **不做强烈阴影对比**：亮暗反差过大会让"暗处的弹幕"看不清，农场应保持**均匀明亮**
- 谷仓等室内场景单独降一档亮度，但**不低于可读阈值**（必要时给室内加补光）

## 3. 关卡结构：用篱笆把户外切回「房间」

### 3.1 核心矛盾与解法

ID-005 要求「一格一格独立房间，清完怪开门」。但农场是开阔户外，天然没有房间的墙。

**解法：田垄网格 + 篱笆门。** 整张农场被木栅栏 / 灌溉渠 / 干草墙切成若干矩形田块，
每块就是一个「房间」；清完一块，篱笆门开启通往下一块。

| 房间制要素 | 农场的对应物 |
|---|---|
| 墙 | 木栅栏 / 树篱 / 灌溉渠 |
| 门 | 篱笆门（木栅门，清怪后倒下） |
| 走廊 | 田埂小径 |
| 房间锚点 | 复用 `RoomBehaviour._doorAnchors` |

这样既保住了房间图的加载调度与清怪开门逻辑（全部复用现成代码），
又让"户外农场"在视觉上成立 —— 而且**篱笆是通透的**，玩家能看见下一块地的敌人，
这反而缓解了地牢里"不知道门后有什么"的紧张感，更契合轻松基调。

### 3.2 房间图（单局）

```text
                    [ 晒谷场 · Boss 房 ]
                            ▲
        ┌───────────┬───────┴───────┬───────────┐
        │           │               │           │
   [ 玉米地 ]  [ 谷仓·战斗 ]   [ 温室·战斗 ]  [ 磨坊·精英 ]
        │           │               │           │
        └─────┬─────┴───────┬───────┴─────┬─────┘
              │             │             │
        [ 鸡舍·战斗 ]  [ 水井·抽奖 ]  [ 瓜田·宝箱 ]
              │             │             │
              └─────────────┴─────────────┘

```

- 主干战斗房：玉米地 → 谷仓 / 温室（二选一分支）→ 精英房（磨坊）→ Boss（晒谷场）
- 特殊房：鸡舍（战斗+整活）、水井（抽奖）、瓜田（宝箱）、市集（商店，可后续加）
- 分支结构复用 ID-005 的走廊选路，不新增系统

## 4. 敌人设计

全部遵守两条铁律：**有前摇（ID-008，0.3-0.5s）** + **弹幕可预判（§5.1 冲突一）**。
造型一律 Q 版圆润，死亡时炸成卡通碎片（ID-006）。

| 敌人 | 造型 | 攻击 / 弹幕 | 前摇表现 | 应对 |
|---|---|---|---|---|
| **冲锋鸡** Chicken Rusher | 圆滚滚橙红小鸡，跑起来翅膀乱扇 | 无弹幕，直线冲撞（可被翻滚躲） | 原地扑翅 + 身体后仰 0.4s | 翻滚无敌帧 / 侧向走位 |
| **稻草人枪手** Scarecrow Gunner | 破草帽、纽扣眼 | 3 发扇形弹幕（弹速 18，慢） | 抬手举枪 + 充能橙光 0.45s | 读招后侧移 |
| **洒水器炮台** Sprinkler Turret | 草坪洒水器，旋转喷头 | 规律旋转环形弹（完全可预判） | 喷头嗡鸣 + 水压上升 0.5s | 卡节奏穿过间隙 |
| **南瓜地雷** Pumpkin Mine | 咧嘴笑的南瓜，静止 | 接近后膨胀爆炸（范围伤害） | 膨胀 + 引信嘶声 0.6s（更长，因为是必中范围） | 拉开距离 / 主动引爆打怪 |
| **愤怒公牛** Bull | 肌肉牛，鼻孔喷气 | 长距离冲锋，撞墙自己眩晕 | 刨蹄 + 低头 0.5s | 侧闪让它撞墙（整活） |
| **蜂群** Bee Swarm | 一团黄色小球 + 翅膀 | 环形 6 发慢速弹 + 追击 | 嗡鸣渐强 + 群体聚集 0.4s | 翻滚穿过 / 优先集火 |

**同屏上限 5-8 个**（§5.1 冲突一第 3 条）。鸡群可用"小怪波次"分摊，不一次堆满。

**生成规则**：沿用 `CombatRoom` 已有的「玩家正面 ±120° 扇形」约束；
玉米地等视线受阻区域**禁止刷怪**，或强制走 `WarnThenSpawn` 延迟 + 屏幕边缘预警。

## 5. Boss：稻草人王（Scarecrow King）

### 5.1 为什么不选母鸡女王 / 拖拉机

- 母鸡女王：萌度高，但弹幕创意弱（下蛋 ≈ 抛物线，第一人称下难读）
- 暴走拖拉机：压迫感强，但冲撞为主，弹幕成分少，与「弹幕射击」核心偏离
- **稻草人王**：能站桩发弹幕、造型经典、且**帽子切换本身就是超强前摇信号**

### 5.2 核心机制：换帽子 = 换招式

Boss 头顶的帽子就是**招式预告**（这是 ID-008 前摇设计的极致化 —— 玩家看到帽子就知道要出什么）：

| 帽子 | 招式 | 弹幕 | 前摇 | 破法 |
|---|---|---|---|---|
| 🎩 破草帽 | 环形扫射 | 8 发环形弹，慢速扩散 | 举手 0.5s + 帽子发光 | 找缺口穿过 |
| 🤠 牛仔帽 | 冲锋 | 直线冲撞，沿途留草屑 | 低头刨地 0.6s | 侧闪，引它撞谷仓 |
| 🎃 南瓜头 | 召唤 | 抛出 4 个南瓜地雷 | 举南瓜 0.5s | 打爆南瓜反伤它 |
| 👑 王冠（狂暴） | 全屏乱射 | 交替环形 + 扇形 | 全场变暗 0.8s | 躲进干草堆（无敌） |

**换帽动画本身就是 0.5-0.8 秒的前摇窗口**，玩家有充足时间读招。
这是把「可读性」做成 Boss 核心机制，而不是靠数值。

### 5.3 阶段

- **P1（100%-60%）**：草帽 ↔ 牛仔帽交替，节奏舒缓
- **P2（60%-30%）**：加入南瓜头召唤，场地出现南瓜地雷
- **P3（30%-0%）**：换王冠狂暴，弹幕密度提升但**保持规律**（不随机化 —— 随机 = 不可读 = 违反冲突一）

> ⚠️ **刻意不做随机弹幕**。狂暴阶段靠"节奏加快"而不是"形状随机"提升难度。

## 6. 整活机制（ID-004 在农场的落地）

「整活」必须有机制支撑，不能只靠美术。农场是整活密度最高的主题，以下都是**可交互物件**，不是装饰：

| 机制 | 触发 | 效果 | 整活点 |
|---|---|---|---|
| **骑猪** | 靠近猪按 E | 骑上冲刺，撞飞敌人（也撞飞队友） | 队友正在瞄准时被猪撞飞 |
| **干草堆** | 推 / 撞 | 可躲藏（敌人失去目标）；可把队友推进去 | 把倒地队友藏进草堆"假装救援" |
| **爆炸南瓜** | 射击 | 连锁爆炸，把附近所有人（含队友）炸飞 | 一人引爆，全队升天 |
| **蜜蜂窝** | 射落 | 蜂群追击**最近的人**（可能是队友） | 打下来结果追自己 |
| **风车叶片** | 靠近旋转叶片 | 被打飞（无视阵营） | 把 Boss 骗到叶片下 |
| **施肥池** | 踩入 | 打滑，移动失控 | 滑进弹幕里 |
| **引诱鸡群** | 语音能量值 | 对着麦克风学鸡叫 → 鸡群朝你跑来 | **自研语音独门优势**，见下 |

### 6.1 语音联动（独门优势）

语音链路是自研的，能拿到麦克风能量值 → 可做**「学鸡叫引诱鸡群」**：

- 玩家对着麦克风大声叫 → 附近鸡群被吸引，朝声源聚集
- 可以用来**把怪引到陷阱**，也可能**引到队友身上**（整活）
- 商业语音方案（Vivox 等）拿不到实时能量值，这个别人抄不了

这与 ID-004 的「喊得越大声，武器威力越高」是同一套底层能力（音频能量 → 游戏机制）。

## 8. 可读性适配（冲突一在农场的具体落地）⚠️

这是农场主题**最大的技术风险**。三个具体问题与解法：

### 8.1 明亮场景 → 自发光子弹的可读性下降

**问题**：§5.1 冲突一说子弹要"自发光 + 拖尾"，那是为了暗色地牢。
农场是白天户外，浅色天空 + 麦田背景下，**发光的亮色子弹会"融"进背景**。

**解法**（`ProjectileVisual` 已有机制，农场必须强制开启）：

1. **描边（inverted hull）强制开启** —— `ProjectileVisual._useOutline = true`，
   用**深色描边**（不是白描边）包住亮色弹体，保证在亮背景上也能分辨
2. **弹幕用冷色**（青 / 紫），场景用暖色 —— 色相对比优先于明度对比
3. **拖尾不受光**，且长度足够（0.25s → 农场建议 0.35s）
4. 天空刻意降饱和（见 §2.2），把天空让给弹幕

> 这条要写进美术规范：农场主题的弹幕资产**必须**带描边，否则不予验收。

### 8.2 玉米地遮挡视线 → 偷袭风险

**问题**：高作物遮挡 = 玩家看不见敌人 = 违反「敌人生成在正面扇形」的初衷，
退化成"莫名其妙地死"。

**解法**：

1. 玉米地**只做齐腰高度**（不挡平视视线），或做成稀疏行列 + 顶部剪影
2. 视线受阻区域**不放刷怪点**；若剧情需要，强制走 `CombatRoom.WarnThenSpawn`：
   先 1.2 秒屏幕边缘红光预警，再出怪
3. 室内（谷仓）转角同样适用：`Telegraph` 前摇 + `ThreatIndicator` 双保险

### 8.3 开阔场地 → 同屏敌人失控

**问题**：空旷场地容易让敌人数量超出 5-8 上限。

**解法**：用**篱笆 / 干草墙 / 沟渠把大场地切成若干战斗单元**（§3.1 的网格），
每个单元独立结算波次；`CombatRoom._maxConcurrent` 保持 6。

## 9. 技术要点

| 项目 | 说明 |
|---|---|
| **房间实现** | 每个田块 / 建筑一个 Prefab，挂 `CombatRoom`（或对应特殊房），带 `_doorAnchors` 锚点 |
| **加载调度** | 复用 `RoomStreamer`（原 `IslandStreamer`），按跳数加载，迟滞防抖已内建 |
| **刷怪约束** | 复用 `CombatRoom.PickSpawnPoint()` 的正面 120° 扇形 + 背后延迟预警 |
| **弹幕** | 复用 `BulletPattern` SO；农场新增 3-4 个模式资产，**不改代码** |
| **敌人** | 复用 `EnemyBase` 状态机 + `Telegraph` 前摇；新敌人 = 新 Prefab + 新 Pattern 资产 |
| **Boss** | 新增 `BossScarecrow`（继承敌人基类思路），换帽即切 `BulletPattern` |
| **武器** | 全部 `WeaponData` 资产 + 组合 `WeaponBehaviour`，零新代码 |
| **网络** | 全部服务器权威（伤害 / 前摇 / 状态）；客户端只做表现与预测 |
| **存档** | **完全局内**，不进存档（闯关进度归房主，但一局结束即弃） |
